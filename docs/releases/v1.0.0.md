# MaskRiver v1.0.0

**Stable within the supported scope below.** This is not a claim of production
PII accuracy, legal anonymisation, universal database support, or exactly-once
recovery.

## Supported scope

- Linux amd64 release binary, built from this tag.
- SQLite M1 workflow: Scan -> Preview -> separate Ed25519 Approve -> Apply ->
  Validate, including multi-table scopes and strict validation.
- MySQL 8.0.46 M1 workflow with two DSNs, on an isolated server, verified by the
  pinned network-disabled CI container.
- SQLite `m2-stream-v1` bounded streaming/outbox and local
  `m2-recovery-v1` checkpoint/status/resume on Linux amd64 rollback-journal
  SQLite with deterministic strategies.
- Windows amd64 and macOS arm64: non-streaming SQLite M1 via CI; no release
  artifact is published for them.
- Cross-built but not runtime-verified: macOS amd64, Linux arm64.

## Changes since v0.2.1-preview

- M3-1: strict full-scan validation with SQLite quick/FK integrity checks,
  non-NULL-to-NULL writer refusal, approval clock-skew alignment.
- M3-2: real MySQL 8.0.46 CLI with distinct-database identity checks, full
  planned-table content binding, logical schema mapping, CHECK TABLE + visible
  FK orphan strict validation, DSN safety gates, and isolated CI E2E.
- M3-3: `help <command>`, executable tutorials and troubleshooting/operations
  runbooks.
- M3-4: 345-case generated detection holdout and generated masking invariants,
  with explicit limitations.
- M3-5: macOS non-streaming M1 CI and cross-build evidence for unsupported
  runtime targets.

## Explicit limits / non-claims

- MySQL streaming/outbox/checkpoint/recovery is **not supported** and is refused.
- Windows/macOS streaming/recovery and WAL recovery are not supported.
- No persistent mapping, cross-store mapping atomicity, general exactly-once,
  real power-loss durability guarantee, or cross-database transaction.
- MySQL strict validation checks `CHECK TABLE ... QUICK` and visible FKs touching
  the planned table; it is not a whole-server, replication or CHECK-expression
  verifier. Cross-schema FKs invisible to the account cannot be checked.
- Detection/masking evaluation is synthetic and repository-authored; no human
  adjudication, production accuracy or anonymity claim.
- The local trust-file + reviewer-key boundary is not RBAC; whole-history or
  revocation rollback is not detected.
- MySQL evidence is limited to 8.0.46 on the pinned CI image. Other versions,
  authentication plugins and TLS/production topology are unverified.

## Install and verify

```sh
sha256sum -c SHA256SUMS
tar -xzf maskriver-v1.0.0-linux-amd64.tar.gz
cd maskriver-v1.0.0-linux-amd64
./maskriver --version
```

Use only authorized, isolated, disposable copies. MySQL requires two DSNs for
distinct databases and a least-privilege account with metadata visibility; see
the [guides](../guides/README.md).
