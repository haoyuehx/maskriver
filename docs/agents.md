# 四人协作与可选 AI 工具

项目采用独立克隆、功能分支、PR、统一 CI 和代码评审的协作模式，完整边界见 [AGENTS.md](../AGENTS.md)。Windows、Linux、macOS 成员享有相同的开发入口。

## 职责不是机器或 Agent

四位成员分别认领 go-db、go-detect、go-mask、go-verify 模块任务，也可经协调调整分工。Main 是集成与共享契约协调职责，reviewer 是独立评审职责；均由成员兼任，不要求第五个人。

| 模块 | Issue | 范围 |
|---|---|---|
| go-db | #5 | internal/db |
| go-detect | #6 | internal/detect |
| go-mask | #7 | internal/mask |
| go-verify | #8 | internal/verify、tests |

共享类型、依赖、测试环境及文档由 Main 协调。未经授权不顺手修改其他模块。认领时写明负责人、分支、基线 SHA、代码范围和验收测试，不需要记录绝对路径。

## 可选工具

成员可以手写代码或使用获授权的 AI 工具。`.pi/` 和本机诊断脚本是旧的可选工具配置，不是 CI、Issue 或参与项目的前置条件。使用者须自行核对适用性；旧配置不能覆盖当前协作规则，也不能据此启动 Agent。

不要求特定模型、配额、个人会话、补丁缓存或 Native worktree。并发写入需独立目录，但可用独立克隆或自己管理的工作树。设备持有人负责其本地资源，不将清理任务混入产品 Issue。

## 交付与评审

通过 PR 交付代码和合成测试，提交实际测试结果与未验证项；统一 CI 通过后由非作者成员或获授权 AI Reviewer 审查。AI 评审不能替代维护者最终合并决定。评审发现写入 PR，修复由模块负责人处理；禁止上传会话、凭证、原始个人数据或数据库文件。
