# MaskRiver v0.2.1-preview — strict validation hardening

**Status:** limited public pre-release. Not production-stable. Linux amd64, local SQLite only.

This release is the M3-1 security/quality slice on top of v0.2.0-preview.1.
It does **not** include the MySQL CLI, MySQL recovery, persistent mapping, or
Windows/macOS streaming/recovery.

## Changes

- `--strict` is now a real verifier mode: it requires `RowLimit=0` and an
  adapter integrity check on every planned table on source and target. SQLite
  uses `quick_check` plus a database-wide `foreign_key_check`; a reader without
  the capability fails closed. MySQL strict remains unsupported/UNVERIFIED.
- `internal/db` now rejects non-NULL -> NULL replacements (`ErrUnsafe`), closing
  Issue #9 P2-1 at the Writer layer.
- Runner approval accepts the same 5-minute future-issued clock skew as the
  history store (Issue #9 P2-8).
- Tests and M3 tracking docs.

## Support and non-claims

Linux amd64, local SQLite, rollback journal, `synchronous=FULL`, authorised
disposable copies. M1 workflow, bounded streaming, outbox, checkpoint/status/
resume and deterministic-strategy recovery remain as verified in
v0.2.0-preview.1. MySQL CLI/recovery, Windows/macOS streaming/recovery, WAL
recovery, cross-store atomicity, generic exactly-once, power-loss durability,
production PII accuracy and anonymisation are not supported. Strict MySQL is
UNVERIFIED and fails closed.

## Install

```sh
sha256sum -c SHA256SUMS
tar -xzf maskriver-v0.2.1-preview-linux-amd64.tar.gz
cd maskriver-v0.2.1-preview-linux-amd64
./maskriver --version
```
