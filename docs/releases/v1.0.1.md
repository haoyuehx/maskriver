# MaskRiver v1.0.1

**Patch release: fails closed on unsafe SQLite apply targets.** No new product
features and no contract changes.

## Fix

Legacy (non-streaming) SQLite `mask --apply` now refuses a target whose journal
mode is WAL, MEMORY or OFF before opening a Writer. Previously a WAL target
could commit masked rows only to the `-wal` sidecar while the main `.db` file
remained byte-identical; a copied single-file target could still contain the
original values even though Apply reported Complete.

The check uses the same quiescent-journal gate as the source snapshot and the
streaming path. The refusal is `incomplete coverage` and exits non-zero. This
closes the target-side half of issue #9 P2-5; the CLI digest still hashes only
the main target file, which is safe because WAL targets are now unreachable.

## Compatibility

- Supported scope is unchanged from v1.0.0.
- SQLite rollback-journal (`delete`/`truncate`/`persist`) apply remains supported.
- SQLite and MySQL 8.0.46 M1 CLI, strict validation, Ed25519 approval, SQLite
  streaming/outbox and `m2-recovery-v1` checkpoint/status/resume are unchanged.
- Frozen contracts are unchanged: `m1a-v1`, `m2-stream-v1`,
  `m2-approval-binding-v1`, `m2-recovery-v1`.
- MySQL streaming/recovery, Windows/macOS streaming/recovery and WAL recovery
  remain unsupported.
