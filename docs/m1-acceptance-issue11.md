- **MySQL 用户 CLI 全流程**：仅适配器组件测试（隔离 MySQL 8.0.46）；CLI 只实现 SQLite。
- **断点恢复 / checkpoint / 跨进程幂等重放 / exactly-once**：未实现。
- **生产级检测准确率**：74 条自编样本、开发集即评估集；姓名规则 P=0.500 / R=0.750。
- **macOS**：CI 矩阵只有 Ubuntu / Windows。

- **持久映射、全局唯一性、匿名化、参照完整性**：未实现/未验证。
- **WAL 目标的 journal mode**：目标端未校验；CLI e2e 的 `targetDigest` 只哈希主文件（#9 登记表 P2-5，另一清单，见 §9）。

## 7. 发布范围

**可以宣称**

- 一个在**授权、隔离的合成 SQLite 库**上完成 Scan → Preview → 审核 → Apply → Validate 的 M1 受限版本，写入只能由显式 `--apply` 触发。
- 已知 P2 与 UNVERIFIED 清单**公开可查**（本文件、[测试计划](test-plan.md)、[#9 验收报告](issue9-acceptance-report.md)）。
- 门禁与 fail-closed 行为、以及“脱敏 ≠ 匿名化、确定性 ≠ 无碰撞”的边界表述。

**必须不宣称**

- 不得宣称 M1 已全面发布、已通过“完整安全批准”，或可处理生产/真实个人数据。
- 不得宣称支持 MySQL CLI、断点恢复、exactly-once、高吞吐并发、生产级 PII 识别准确率或 macOS 支持。
- 不得宣称具备匿名化、无碰撞或参照完整性保证，也不得宣称 `--strict` 提供了额外严格检查。
- 不得宣称 Dry Run 在任何情况下都“不新增任何文件”（F1：WAL 源被拒时仍可能新增 sidecar）。
- 不得宣称审批等于 RBAC 或抗内部人：审批信任边界是**本地签名边界**，`ReviewerID` 只是自填标签，同一操作者若同时控制 trust file 与审核私钥，工具不会阻止。
- 不得宣称历史存储防篡改：能写 store 目录者可恢复旧的有效记录或撤销前文件（#9 登记表 P2-6）。
- 不得把 `pkg/contracts` 描述为稳定公共 SDK。

**当前状态**

- `docs/licenses/` 现存 **12** 份文本，与 [attribution.md](attribution.md) 的归属表 **1:1**，且与模块缓存**逐字节一致**（2026-10-19 机械复核，`cmp`，12/12）。

**仍未完成（发布前必须核查）**

1. **NOTICE / 发行包载体**：仓库内**没有** `NOTICE` 文件，也没有把许可证清单打进发行包的机制。MPL-2.0 要求二进制分发时提供获取对应源码形式的途径——[attribution.md](attribution.md) 已声明该义务，但**尚未落地到任何发行工件**。
2. **内置第三方声明未捕获**：`modernc.org/libc@v1.77.1` 的模块目录内含 `LICENSE-3RD-PARTY.md`（Go / musl / go-netdb / nixpkgs 等被编译进去的第三方声明），`docs/licenses/` **未包含**该文件。仅收录模块顶层 `LICENSE` 不足以覆盖它。
3. **版本可定位但获取路径未记录**：归属表给出模块与版本号，但没有记录发行时如何让接收方取得对应源码。

**关键提醒**：**仓库里存在 `docs/licenses/` 目录，本身并不使任何发行工件合规。** 合规对象是**发布出去的那个二进制包**及其随附材料，而不是仓库目录结构。上列三项必须在每次实际发布前逐项核查并留证；本文不声称它们已完成。
