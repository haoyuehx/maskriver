# MaskRiver v0.2.0-preview.1 — SQLite Streaming & Recovery Preview

这是 MaskRiver 的**受限 Pre-release**，不是生产稳定版。仅面向获得授权、隔离且可丢弃的**本地 SQLite** 数据库副本。

## 新增能力

- **M1 核心 SQLite 工作流**：`scan` → `preview` → Ed25519 `approve`（独立进程）→ `mask --apply`（新进程）→ `validate`。
- **M2 有界 Streaming Apply**：`--streaming`、独立 `--budget-file`、1–16 workers、字节感知 `MaxRowBytes`、确定性分页。
- **事务 Outbox**：业务 UPDATE 与回执 INSERT 在同一 SQLite 事务；`commit_unknown` 保守分类，不自动重试。
- **Checkpoint / Status / Resume**：`init-recovery`、只读 `status`、显式 `--resume`；业务 UPDATE + receipt + progress + manifest CAS 同事务。
- **幂等故障恢复**：已提交前缀通过确定性重算校验后跳过；未提交后缀必须仍等于源值；目标外部修改、错误 Key、快照漂移和冲突 fail closed。
- **真实 CLI 故障注入回归**：第 1/10/100/500 批中断、跨表、Validate 前后、Commit 前后恢复，恢复结果与不中断执行一致。

## 实际支持范围

- Linux amd64。
- 本地 SQLite，rollback journal，session `synchronous=FULL`。
- 获授权的隔离、可丢弃数据库副本。
- 显式审批与写入授权：M1 需要 `--apply` + `--approved` + 有效 Ed25519 记录；M2 需要独立 `--streaming` 审批。
- 恢复仅支持纯确定性策略白名单：`null`、`blank`、`redact`、`format_random`、`fake_email` 与九种 `cn_*`。
- 恢复需要显式 `init-outbox` 与 `init-recovery`；旧 Issue #13 运行不会被自动伪装为可恢复。

## 已验证证据

- Issue #9 / #11：SQLite 多表 CLI、签名审批、静态安全门禁、批次故障与独立验收。
- Issue #13：`m2-stream-v1`、事务 Outbox、资源预算、Linux SQLite Streaming。
- Issue #14：`m2-recovery-v1`、事务 Checkpoint、只读 Status、幂等 Resume、CommitUnknown 重核、真实 CLI 中断恢复与 10k/100k/1M 规模证据。
- 最终 CI：Ubuntu/Windows 测试与 vet、Ubuntu race、隔离 MySQL 8.0.46 组件测试、benchmark/stress。
- 发行包：确定性归档、SHA256SUMS、NOTICE/许可审计、解压后二进制 Smoke 与 Recovery E2E。

## 不支持或未验证

- MySQL CLI 全流程与 MySQL Recovery。
- Windows/macOS Streaming 或 Recovery。
- WAL Recovery。
- 分布式或通用 exactly-once。
- 跨存储 Mapping 原子性。
- 真实断电持久性证明。
- 生产级 PII 识别准确率、法律意义上的匿名化、替换值永不碰撞。
- 完整防篡改历史。
- `--strict` 的独立数据库层严格语义（当前由 Warning/覆盖不完整路径 fail closed，但不等于新增语义）。
- 全局无界条件下的固定 RSS；所有文件系统故障模式。
- 审批运行期的持续复核（仅在 Apply/Resume 开始时验证有效期与撤销状态）。

## 安装与验证

```sh
sha256sum -c SHA256SUMS
tar -xzf maskriver-v0.2.0-preview.1-linux-amd64.tar.gz
cd maskriver-v0.2.0-preview.1-linux-amd64
./maskriver --version
./maskriver --help
```

请只对授权、隔离、可丢弃的 SQLite 副本运行。默认 Preview 不写入；只有显式 `--apply` 和有效审批才可能写入。

## 已知风险

- 恢复仅在上述本地 SQLite 条件下经过验证；不得外推到 MySQL、WAL 或其他平台。
- `validation_failed` 对 Resume 是终止状态，需要人工调查或新运行。
- 恢复元数据（含 key-check 值）保留在脱敏后的数据库中；不要把它当作不存在。
- Key 必须是 CSPRNG 生成的至少 32 字节高熵秘密，不应使用口令。
- 构建与规模数据是单机合成样本；1M 为单次样本，不代表生产吞吐。
